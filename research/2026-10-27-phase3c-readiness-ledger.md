### Final scientific-integrity correction

Independent reproduction found three defects in the initial package:

1. Calibration dereferenced trace paths for held-out partitions before filtering eligibility.
   Split-registry v2 now requires verified demand identity for every pool, requires traces only
   for training/calibration rows, and forbids non-null held-out trace identities.
2. Registry-declared physical fingerprints were trusted. The validator now recomputes the
   Phase 3.0A canonical ID-insensitive fingerprint directly from each hash-verified explicit
   demand XML before uniqueness checks. Renaming vehicle IDs cannot create an independent
   realization; genuine distinct schedules sharing one template remain valid.
3. The descriptive overall estimator weighted profiles by cell count. It now averages profile
   means. The known-answer `[-10,-10]` morning and `[+10]` night example returns `0`, not
   `-3.3333`. A separate complete-coverage validator checks four profiles, five checkpoint-bound
   policies per arm, ten physical demands per profile, matched SUMO/demand identities, and no
   missing, duplicate, failed or unbalanced cells. Because the candidate pairing rule remains
   null, publication inference remains unavailable.

Calibration additionally requires all four profiles and the hash-bound protocol
`sumoflow-reward-calibration-protocol-v1`. That protocol fixes the 0.95 positive quantile,
linear method, profile-specific pooling, zero policy, eligible partitions and diagnostic source
protocol. It contains no empirical Tahrir reference values.
